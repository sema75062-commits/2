# План разработки

Поэтапный план. После каждого этапа — рабочий инкремент,
который можно демонстрировать.

## Этап 0. Инфраструктура (1–2 дня) — **СЛЕДУЮЩИЙ**

- [ ] Включить Flyway, перевести `ddl-auto` на `validate`.
- [ ] Создать первую миграцию `V1__create_users_table.sql`.
- [ ] Вынести пароль БД в переменную окружения (`${DB_PASSWORD}`).
- [ ] (опционально) Профили `application-dev.properties` / `application-prod.properties`.
- [ ] Подключить `spring-boot-starter-validation`.

**Результат**: проект запускается, БД управляется через миграции, пароли — в env.

## Этап 1. Полноценная аутентификация (2–3 дня) — закрывает п. 4

- [ ] Расширить `User`: `firstName`, `lastName`, `phone`, `enabled`, `createdAt`.
- [ ] Расширить `RegisterRequest`, добавить валидацию (`@Email`, `@NotBlank`, `@Size`).
- [ ] Реализовать `UserDetailsService` для Spring Security.
- [ ] Включить настоящую авторизацию (form-login или JWT — зависит от выбора фронта).
- [ ] Эндпоинты: `/auth/register`, `/auth/login`, `/auth/logout`.
- [ ] Глобальный `@RestControllerAdvice` (дубликат e-mail → 409, валидация → 400).
- [ ] Защита `SecurityConfig`: `/auth/**` — public, остальное — `authenticated()`, отдельные ручки — по ролям через `.hasRole(...)` или `@PreAuthorize`.
- [ ] Исправить опечатку `STUDEN` в комментарии `User.java`.
- [ ] В `UserService.register()` — проверка дубликата e-mail.

**Результат**: пользователь может зарегистрироваться, войти, выйти; доступ ограничен ролями.

## Этап 2. Доменная модель (3–4 дня)

Добавить сущности, миграции, репозитории:

- [ ] `Subject` (предмет)
- [ ] `Group` (учебная группа) — если решено использовать
- [ ] `Lesson` (занятие: предмет, преподаватель, группа, дата/время, тип)
- [ ] `Grade` (оценка)
- [ ] `Course`, `CourseMaterial`
- [ ] `Test`, `Question`, `AnswerOption`, `TestAttempt`, `TestAnswer`
- [ ] `News`, `Event`, `GalleryItem`
- [ ] Связи: `User`(teacher) ↔ `Subject` (Many-to-Many), `User`(student) ↔ `Group` (Many-to-One)

Каждая сущность — отдельная Flyway-миграция.

**Результат**: схема БД покрывает все требования; есть пустые репозитории для каждой сущности.

## Этап 3. Публичная часть (3–4 дня) — закрывает п. 3

- [ ] Главная, «О школе», преподаватели, новости, галерея, контакты, афиша.
- [ ] Если SSR — Thymeleaf-шаблоны; если SPA — REST + отдельный фронт.
- [ ] CRUD для админа: новости, события, галерея, профили преподавателей.

## Этап 4. ЛК ученика (3 дня) — закрывает п. 5

- [ ] `/api/student/me` — профиль, редактирование.
- [ ] `/api/student/schedule` — расписание (из `Lesson`).
- [ ] `/api/student/exams` — расписание зачётов/экзаменов.
- [ ] `/api/student/grades` — журнал оценок.
- [ ] `/api/student/courses` — доступные курсы.
- [ ] Защита: только `ROLE_STUDENT`, доступ только к своим данным.

## Этап 5. ЛК преподавателя + журнал (3–4 дня) — закрывает п. 7, 8

- [ ] Список учеников/групп преподавателя.
- [ ] Просмотр и редактирование журнала: ввод/редактирование оценок.
- [ ] Расписание преподавателя.
- [ ] Защита: преподаватель видит только своих учеников.

## Этап 6. Электронные курсы и тесты (4–5 дней) — закрывает п. 6

- [ ] Преподаватель: создание курса, загрузка материалов (`MultipartFile` + хранилище).
- [ ] Преподаватель: создание тестов с вопросами single/multi choice.
- [ ] Ученик: просмотр материалов, прохождение теста.
- [ ] Автоматическая проверка теста + ручная корректировка оценки.

## Этап 7. Администрирование (2–3 дня) — закрывает п. 9

- [ ] CRUD пользователей (создание преподавателей админом).
- [ ] Блокировка пользователей (`enabled = false`).
- [ ] Управление справочниками: предметы, группы.

## Этап 8. Полировка

- [ ] Логирование действий (audit log).
- [ ] Тесты (юнит + интеграционные с Testcontainers для PG).
- [ ] Документация API через `springdoc-openapi`.
- [ ] Деплой: Docker + docker-compose (PG + приложение).
- [ ] Резервное копирование БД.
